## Resumen ejecutivo

La documentación de Faro está sistemáticamente desfasada respecto al código: el grueso de los 155 gaps confirmados son endpoints REST reales, montados y consumidos por el frontend, que no figuran en la tabla "Superficie de la API REST" del README ni en el OpenAPI servido en `/docs` (que solo anota 2 de decenas de handlers). El problema más grave es de seguridad/correctitud: la doc anuncia un modelo de auth de ingesta (`FARO_INGEST_TOKEN`) que el backend nunca lee, README.en.md afirma que el dashboard no tiene auth citando un ADR ya superseded, y el flush por `sendBeacon` del SDK browser usa un `_token` en query string que el backend ignora, perdiendo datos al cerrar la pestaña. Dominios enteros (cohorts, product-users, integrations/channels, funnels avanzados, insights, feature-flags writes) existen en producción sin ninguna guía de usuario. Los READMEs per-paquete de los SDKs están atrasados frente a features mayores ya publicadas (tracing OTel, métricas nativas, session replay) y hay inconsistencias que rompen compilación (`ginfaro.Middleware()` vs `Tracing()`, `close(timeoutMs)` en Kotlin). Como atenuante recurrente, mucha de esta superficie SÍ está documentada en fuentes secundarias (UI in-app, `sdk-docs.ts`, `sdks/README.md` central), pero no donde el integrador la busca primero.

## Gaps por severidad

### 🔴 Alta
- Auth de ingesta: la doc presenta `FARO_INGEST_TOKEN` como Bearer canónico pero el backend nunca lo lee; la auth real es por-proyecto (`FARO_BOOTSTRAP_INGEST_TOKEN` / `POST /projects`). Un valor distinto en prod da 401. Reescribir README/environment.md/ADR-0005 y marcar `FARO_INGEST_TOKEN` como muerta (ingest, projects).
- `sendBeacon` manda el token como `?_token=` que el backend no lee → flush en cierre de pestaña da 401 y pierde los últimos eventos rrweb/logs/events; afecta replay, logs y events del SDK browser. Documentar y/o corregir (leer query param o middleware que promueva a header) (sessions-replay).
- README.en.md afirma "No authentication on the dashboard API" y cita ADR-0005 como vigente, contradiciendo la auth nativa real (cookie + Argon2 + 2FA TOTP, ADR-0009). Reescribir la sección "Limitations" del README inglés (auth-account-2fa).
- No existe forma documentada (REST/UI/CLI) de crear/configurar feature flags en `faro.feature_flags`; solo lectura/evaluación está documentada. Documentar el método de alta (hoy: INSERT directo) o exponer endpoint (feature-flags).
- Endpoints REST de canales de integración (`/integrations/channels*`, incl. `/kinds`) sin doc de usuario: el integrador que quiere alertas a PagerDuty no tiene ruta documentada. Documentar el CRUD y el esquema `channel://<id>` (integrations-notify).
- Modelo `CohortDefinition` (event/op/count/last_days/filters/user_filters) que forma el body de `POST /cohorts` sin doc de usuario; solo en spec interna. Documentar el contrato del body (cohorts).
- README per-paquete de `@iaportafolio/node` no refleja v0.2.0/v0.3.0 (tracing OTel auto-instrumentado ni API de métricas), describiendo el estado pre-0.2.0. Actualizar el README a las features publicadas (sdk-node).
- `sdk-docs.ts` documenta `ginfaro.Middleware()` pero el código exporta `ginfaro.Tracing()`; copiarlo no compila. Corregir el catálogo (que alimenta `/docs.md` y `/llms.txt`) (sdk-go).

### 🟡 Media
- Endpoints nativos de ingesta `POST /ingest/spans` y `POST /ingest/metrics` sin doc de usuario; además README dice métricas "solo vía OTLP" pese a existir ingesta nativa usada por el SDK Node. Documentar ambos y corregir la afirmación OTLP-only (ingest, metrics).
- Contrato de product events: el código declara contrato nuevo `batch`/`event` pero la única doc (`sdks/README.md`) muestra solo `events`/`name` legacy (que es lo que envían los propios SDKs). Alinear doc y/o código (ingest).
- Límite duro de 100 eventos/request en `/ingest/events` contradice el `maxBatchSize` default 200 de los SDKs server; un 400 se descarta silenciosamente (pérdida de datos). Documentar el límite y/o bajar el default (ingest).
- Endpoints sin doc de usuario ni en OpenAPI/tabla REST (documentar contrato, params y shape de respuesta): `/services/map`, `/traces` + `/traces/{id}` (filtros y shape), `/services`, `/events/live`+`/events/stats`, filtros y paginación por cursor de `/logs` y `/events`, `/replays`+`/replays/{id}`, `/errors/{fingerprint}/sessions`, `/product-users*`, `/cohorts/*` (retention/overlap/preview/users), `/experiments/analyze`, los 4 endpoints de `/insights/*`, `/dashboard`, `/projects/*` CRUD, `/me/preferences`, `/me/sessions`, `/me/security/2fa/*`, `/auth/*`, CRUD `/users` admin (errors, traces-services, logs-events-explorer, product-users, retention, cohorts, experiments, insights, projects, preferences, auth-account-2fa).
- Funnels: `/funnels/drop-off` y `/funnels/time-to-convert` sin doc; `/funnels/compute` documentado solo como `{steps:[...]}` (faltan params y response); no hay guía de funnels. Crear sección de funnels con los 4 endpoints (funnels).
- Canales de notificación nativos (PagerDuty/OpsGenie/Email-Resend/Slack/Discord first-class) y esquema de config por kind + enmascarado de secretos solo en UI/CHANGELOG, no en prosa de docs. Documentar los 7 kinds y `channel://` (alerts-monitors-anomaly, integrations-notify).
- CRUD de alerts/rules y monitors solo en README; condiciones soportadas (gt/gte/lt/lte/eq), valores de severity y body de incidents/`StatusUpdate` no enumerados. Crear `docs/alerts.md`/`docs/monitors.md` con contratos completos (alerts-monitors-anomaly, errors).
- Cohortes por user properties (`user_filters`), enriquecimiento de user properties vía identify (merge server-side), device breakdown y filtros AND de `/product-users` sin doc. Documentar el dominio product-users (product-users).
- Dos modelos de "retention" coexisten (forward `/retention` vs backward `/cohorts/{id}/retention`) sin que la doc los distinga. Aclarar ambos modelos (retention).
- `environment.md` desactualizado: faltan secciones `FARO_USER_UNIFIER_*` y `FARO_SESSION_*` (6 vars consumidas por el código). Regenerar con `gen-env-reference.sh` (deployment-env, product-users).
- Deploy: docs dicen que chequea `/healthz` pero el workflow usa `/readyz` (semántica distinta); la secuencia documentada omite el step de smoke test post-deploy. Corregir `deployment.md` e `infra/README.md` (deployment-env).
- Makefile (atajos de operación) y `release-images.yml` (imágenes GHCR multi-arch + cosign + tags `core-v*`) sin documentar. Añadir a la guía de operación (deployment-env).
- `product-analytics.md` dice que la reproducción rrweb está "pendiente" cuando el player ya existe y funciona. Marcar como entregado (sessions-replay).
- `/docs`/`/docs.md`/`/llms.txt` anuncian métodos de SDK que no son públicos (`initSessionReplay`, `getOrCreateSessionId`); copiarlos falla. Corregir `sdk-docs.ts` (sessions-replay).
- APIs de tracing manual y métricas de los SDKs ausentes de sus READMEs per-paquete (Node, Python, Go); middlewares Express/Gin/WSGI/ASGI sin guía; product analytics (track/identify/...) ausente de READMEs de Node/Python/Kotlin/Flutter/Expo/Next. Añadir secciones por-SDK (sdk-node, sdk-python, sdk-go, sdk-kotlin, sdk-flutter, sdk-expo, sdk-nextjs).
- `sdks/README.md` afirma que `close()` acepta `timeoutMs` en Kotlin, pero `close()` no tiene parámetro (error de compilación). Corregir a `flush(timeoutMs)` (sdk-kotlin).

Alinear versión, documentar `scrubUrlQuery`, corregir firma (sdk-nextjs).
- Auto-correlación de logs con spans subdocumentada (README solo cubre `track()`); SDK Python ya exporta spans propios pero la doc dice que aún no tiene auto-tracing. Actualizar (sdk-node, sdk-python).

## Recomendaciones priorizadas

1. **Corregir la auth de ingesta primero (alta, impacto prod directo).** Reescribir README/`environment.md`/`.env.example`/ADR-0005 para describir el modelo real por-proyecto (`FARO_BOOTSTRAP_INGEST_TOKEN` + `POST /projects`), marcar `FARO_INGEST_TOKEN` como variable muerta, y documentar el header `x-faro-token`. Es el gap que causa 401 silenciosos en producción para integradores nuevos.
2. **Resolver el bug de `sendBeacon` (alta, pérdida de datos).** Decidir entre arreglar el backend (leer `_token` query o middleware que lo promueva a header) o documentar la limitación; afecta replay, logs y events del SDK browser al cerrar pestaña. No es solo doc: hay pérdida real.
3. **Sincronizar README.en.md y la doc de auth del dashboard (alta).** Eliminar "No authentication on the dashboard API" / ADR-0005-vigente y documentar la auth nativa (cookie+Argon2+2FA, ADR-0009) y los endpoints `/auth/*`, `/me/*`, CRUD `/users` con sus contratos.
4. **Reconstruir la "Superficie de la API REST" como referencia completa (media, alto alcance).** La tabla del README omite dominios enteros (cohorts, product-users, integrations, funnels avanzados, insights, sessions/replay, projects, preferences, services/map). Priorizar generarla desde OpenAPI: anotar handlers con `#[utoipa::path]`/`ToSchema` (deuda ADR-0006) para que `/docs` deje de cubrir solo 2 endpoints y la referencia sea automática y verificable, en vez de una tabla manual perpetuamente desfasada.
5. **Documentar el alta de feature flags y los canales de integración (alta).** Son features completas e invisibles desde la doc: cómo crear/configurar flags, y cómo registrar canales (`/integrations/channels`, kinds nativos, `channel://<id>`, config y enmascarado de secretos por kind).
6. **Arreglar las inconsistencias que rompen compilación en SDKs (alta/media, fricción inmediata).** `ginfaro.Middleware()`→`Tracing()`, `close(timeoutMs)` Kotlin, métodos fantasma `initSessionReplay`/`getOrCreateSessionId`, firma `captureRequestError` sin `routerKind`. Son copy-paste que fallan al primer intento.
7. **Actualizar READMEs per-paquete y versiones/CHANGELOG de los SDKs (media).** Node a v0.2.0/0.3.0 (tracing+métricas), Python (exporter/tracing y desmentir "aún no"), Go (tracing), y alinear versión Next.js vs "v0.4.0", CHANGELOG Python/Go, conteos Kotlin. Es lo primero que ve el usuario en npm/pub.dev.
8. **Regenerar y completar la doc de operación (media).** Correr `gen-env-reference.sh` (6 vars faltantes), corregir healthz→readyz, añadir el step de smoke a la secuencia de deploy, y documentar Makefile + imágenes GHCR (`core-v*`).
